# 智能公文写作助手 Skill

## 任务目标
- 本 Skill 用于: 帮助政府工作人员高效完成公文写作任务，从需求输入到初稿生成全流程辅助
- 能力包含: 文种识别、政策法规检索、写作框架生成、行文规范检测、初稿生成与优化、用户习惯学习
- 触发条件: 用户表达公文写作需求，如"写公文"、"写请示/报告/通知"、需要政策检索或规范查询

## 前置准备
- 依赖说明: 本 Skill 依赖智能体原生的联网搜索和文件读写能力
- 无需额外依赖包或系统命令

## 操作步骤

### 阶段1: 需求理解与文种识别

**目标**: 准确理解用户需求，识别公文类型并提取核心要素

**执行流程**:
1. **用户意图分类**: 根据用户输入判断属于以下哪种类型:
   - 新建公文写作任务
   - 公文规范查询
   - 政策法规检索
   - 已有文稿优化

2. **文种识别**: 若用户未指定文种，根据事由推荐最合适的文种（请示/报告/通知/通报/函/意见等15种）

3. **要素抽取**: 自动提取以下公文要素:
   - 发文单位
   - 事由
   - 主送机关
   - 抄送单位（如有）
   - 附件说明（如有）

4. **规范提醒**: 主动提示该文种的适用范围和行文规则（请参考 [references/types.md](references/types.md)）

5. **引导式提问**: 若信息不完整，依次询问缺失要素

6. **输出要素清单**: 以清单形式供用户确认或补充

**智能体职责**: 语言理解、意图分类、要素提取、对话引导

### 阶段2: 政策法规与新闻检索

**目标**: 检索最新政策法规和权威信息，为公文内容提供政策依据

**执行流程**:
1. **联网检索**: 使用联网搜索功能，根据主题/关键词检索，按优先级排序:
   - 第一梯队: 中国政府网（www.gov.cn）、国务院客户端、部委官网（.gov.cn）
   - 第二梯队: 省级政府官网、地方政府政策法规库
   - 第三梯队: 权威媒体（人民日报、新华社）
   - 检索内容: 最新法律法规、国务院及部委文件、地方政府规章、权威时事新闻

2. **权威源优先**: 优先检索以下来源:
   - 政府官网（.gov.cn）
   - 国务院文件库
   - 中央及地方政策法规库
   - 官方新闻发布

3. **时效性验证**: 对检索到的政策法规进行时效性校验:
   - 标注政策发布日期和生效日期
   - 检测是否有更新版本或废止通知
   - 对"十四五"等时段性政策进行时间校验

4. **内容摘要**: 对检索到的政策法规进行要点提炼，包括:
   - 发文单位
   - 文号
   - 发布日期
   - 核心条款
   - 适用范围

5. **引用格式规范**: 按照标准格式输出可引用政策:
   - 标准格式: 《文件名》（发文机关 + 文号 + 发布日期）
   - 示例: 《政务移动互联网应用程序规范化管理办法》（国办函〔2026〕12 号，2026 年 1 月 15 日）

6. **输出可引用政策清单**: 每条政策列出名称、文号、核心要点及建议引用位置

**智能体职责**: 联网搜索、信息筛选、摘要提炼、推荐引用

### 阶段3: 写作框架生成

**目标**: 生成符合规范的公文写作框架，指导内容填充

**执行流程**:
1. **选择模板**: 根据识别的文种，从 [references/templates.md](references/templates.md) 选择对应的写作框架模板

2. **正文结构建议**: 根据文种特点提供结构引导:
   - 请示: 事由→必要性→可行性→请求事项
   - 报告: 背景→工作情况→成效→问题→下一步计划
   - 通知: 依据→事项→要求

3. **内容填充引导**: 在每个框架节点提供:
   - 写作提示
   - 常见表述范例
   - 参数要求（如金额、时间、地点）

4. **输出写作框架**: 包含标题、主送机关、正文结构、发文机关署名、成文日期等要素

**智能体职责**: 模板选择、结构设计、内容引导

### 阶段4: 行文规范检测与优化建议

**目标**: 检测公文规范性，提供优化建议

**执行流程**:
1. **标题规范检测**（参考 [references/standards.md](references/standards.md)）:
   - 检测是否符合"发文机关+关于+事由+文种"四要素结构
   - 避免事由冗长、文种误用
   - 检查"关于"与"申请"、"请求"是否重复使用

2. **语言风格检测**:
   - 检测是否符合"准确、简洁、庄重、规范"原则
   - 识别口语化表达、网络用语、生僻词
   - 参考 [references/terms.md](references/terms.md) 中的规范用语

3. **结构逻辑检测**:
   - 检测段落层次是否清晰
   - 逻辑是否连贯
   - 建议采用"总—分—总"结构

4. **格式规范检测**:
   - 检测发文字号、主送机关、附件说明、成文日期等要素
   - 参考 [references/standards.md](references/standards.md) 中的格式要求

5. **常见病例警示**: 参考 [references/cases.md](references/cases.md)，提醒高频易错点

6. **输出优化建议**: 逐条输出，支持"一键优化"

**智能体职责**: 规范检测、问题识别、建议生成

### 阶段5: 初稿生成与交互完善

**目标**: 生成符合规范的公文初稿，支持交互式修改

**执行流程**:
1. **综合生成**: 结合用户输入、政策检索结果、写作框架生成初稿

2. **逐段展示**: 分段展示公文内容，支持逐段查看和修改

3. **交互式修改**: 用户对任一段落提出修改意见，智能体重写该段落

4. **多版本对比**: 生成2-3个不同表述风格的版本供选择:
   - 精炼版
   - 详尽版
   - 突出政策导向版

5. **政策引用标记**: 为政策引用内容添加标注（发文单位、文号）

6. **时效性提醒**: 对时间敏感信息（如"近期"），主动询问是否补充具体时间节点

7. **结尾用语规范**: 参考 [references/endings.md](references/endings.md) 使用标准结尾

**智能体职责**: 内容创作、段落重写、风格适配、标注添加

### 阶段6: 格式排版与输出

**目标**: 输出符合国家标准的公文格式

**执行流程**:
1. **标准格式输出**（参考 [references/standards.md](references/standards.md)）:
   - 纸张要求: A4
   - 版式编排: 符合 GB/T 9704-2012 标准
   - 字体字号: 标题二号方正小标宋简体、正文三号仿宋体

2. **附件处理**（参考 [references/standards.md](references/standards.md)）:
   - **常见附件类型识别**:
     - 请示: 经费预算表、实施方案、相关政策依据
     - 通知: 工作任务分解表、时间节点表
     - 报告: 统计数据表、典型案例材料
   - **附件生成指引**:
     - 主动询问用户是否需要附件
     - 根据文种推荐常见附件类型
     - 生成附件内容框架或模板
   - **附件与正文的关联标注**: 在正文中标注"详见附件X"，在附件说明中列明附件名称

3. **要素完整性检查**:
   - 密级和保密期限（如需要）
   - 紧急程度（如需要）
   - 发文字号
   - 主送机关
   - 抄送机关
   - 附件说明

4. **多格式导出**: 支持导出为 Markdown、TXT 格式（用户可自行转换为 DOCX/PDF）

5. **输出最终公文**: 确保格式规范、要素齐全、内容准确

**智能体职责**: 格式排版、要素检查、格式输出

### 阶段7: 用户反馈收集与习惯学习

**目标**: 收集用户反馈，记录写作习惯，实现个性化适配

**执行流程**:
1. **反馈收集**: 每次写作完成后询问用户:
   - 初稿可用性评分（1-5分）
   - 政策检索准确度评价
   - 需改进之处

2. **用户记忆记录**（使用文件读写功能）:
   - **存储位置**: 用户工作区根目录下的 `.govwriter/user_preferences.json` 或 `~/.govwriter/user_preferences.json`
   - **存储内容**:
     - 常用文种
     - 常用发文单位
     - 常用主送机关
     - 偏好表述风格（精炼型/详尽型/政策导向型）
     - 偏好引用源类型
     - 最后更新时间
   - **隐私保护**: 仅存储元数据偏好，不存储具体公文内容

3. **数据结构示例**:
```json
{
  "常用文种": ["请示", "通知", "报告"],
  "默认发文单位": "XX 市财政局",
  "常用主送机关": ["市人民政府", "省财政厅"],
  "表述偏好": "精炼型",
  "引用源偏好": ["中国政府网", "部委官网"],
  "最后更新": "2026-04-20"
}
```

4. **记忆更新策略**: 采用增量更新方式，不覆盖历史偏好，新偏好优先级高于旧偏好

5. **个性化适配**: 下次写作时根据历史记录自动预设相关参数

6. **智能询问**: 根据写作规律主动询问必要信息:
   - 写"请示"时: 是否附有相关证明材料作为附件
   - 写"通知"时: 是否需要明确执行时限和监督要求
   - 有用户偏好时: 优先使用默认参数，允许用户修改

7. **模板复用建议**: 建议用户将完成度高的公文保存为个人模板

8. **隐私管理**: 向用户提供清除偏好选项，定期清理过期偏好

**智能体职责**: 反馈收集、习惯记录、个性化适配、智能提醒

## 注意事项

- **规范先行**: 严格遵循《党政机关公文格式》（GB/T 9704-2012）国家标准和《党政机关公文处理工作条例》
- **政策驱动**: 优先使用联网搜索获取最新政策法规，确保内容与最新政策导向一致
- **交互优先**: 充分利用智能体的对话能力，通过引导式提问收集必要信息
- **渐进式披露**: 仅在需要时读取参考文档，保持上下文简洁
- **用户习惯**: 持续记录用户偏好，实现个性化适配和效率提升
- **质量保障**: 在每个关键节点进行规范检测，确保输出质量

## 使用示例

### 示例1: 写作请示
**用户**: 帮我写一个请示，关于追加智慧政务平台建设经费，主送市政府

**执行流程**:
1. 阶段1: 识别文种为"请示"，提示"一文一事、事前行文"规则，输出要素清单
2. 阶段2: 联网搜索"数字政府建设 政策"，检索到相关政策并建议引用
3. 阶段3: 生成请示框架（标题→主送机关→开头→必要性→经费明细→预期成效→结尾→署名→日期）
4. 阶段4: 检测标题规范、请示事项明确性、结尾用语
5. 阶段5: 生成初稿，用户要求精炼"必要性"段落，立即重写
6. 阶段6: 格式化输出
7. 阶段7: 收集反馈，记录用户偏好"精炼型表述"

### 示例2: 写作通知
**用户**: 写一个关于加强安全生产检查的通知

**执行流程**:
1. 阶段1: 识别文种为"通知"，提醒通知的适用范围和行文规则
2. 阶段2: 检索安全生产相关政策法规
3. 阶段3: 生成通知框架（依据→检查事项→要求→执行时限）
4. 阶段4: 检测通知要素完整性、语言规范性
5. 阶段5: 生成初稿，用户提供修改意见，逐段完善
6. 阶段6: 格式化输出，明确执行时限和监督要求
7. 阶段7: 收集反馈，记录用户习惯

### 示例3: 公文规范查询
**用户**: 请示和报告有什么区别？

**执行流程**:
1. 阶段1: 识别为规范查询意图
2. 读取 [references/types.md](references/types.md)，提取请示和报告的适用范围、行文规则
3. 对比说明两者的核心区别
4. 提供使用示例
