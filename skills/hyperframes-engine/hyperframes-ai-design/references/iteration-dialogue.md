# 多轮迭代对话模式

本文档定义了 HyperFrames AI 设计助手在多轮对话中的标准交互模式，
包括初次交付后的确认流程、常见修改请求的响应策略和迭代记录格式。

---

## 一、初次交付后的标准确认问题清单

每次完成第一版设计输出后，必须向用户提出以下确认问题（选择最相关的 3-5 个）：

### 视觉风格确认

> 当前使用的是 **{风格名称}** 风格，色彩以 **{主色}** 为基调。
> 这个整体方向符合你的预期吗？还是希望调整为更 **{备选方向A}** 或更 **{备选方向B}** 的感觉？

### 内容完整性确认

> 当前帧包含以下内容：{元素清单}。
> 有没有需要补充或删减的信息？

### 运动节奏确认

> 当前动效节奏为 **{能量等级}**（{时长}s 入场）。
> 是否希望调快一些（更有冲击力）或调慢一些（更沉稳优雅）？

### 排版层次确认

> 主标题当前为 **{字号}px**，副标题为 **{字号}px**。
> 层次感是否足够清晰？标题是否需要更突出？

### 色彩情绪确认

> 强调色使用的是 **{色值}**，整体色温偏 **{冷/暖}**。
> 这个颜色方向是否与你的品牌或活动调性匹配？

---

**提问原则**：
- 每次最多提 3 个问题，避免信息过载
- 优先提与本次设计最大不确定因素相关的问题
- 问题应给出具体选项，而非开放式询问

---

## 二、常见修改请求的响应模式

### 修改请求类型 1：调整颜色

**用户可能说**："颜色太冷了"、"能换个暖一点的"、"主色改成蓝色"、"强调色用橙色"

**响应策略**：
1. 确认修改范围：仅改强调色，还是整体配色方案
2. 如果只改强调色：仅修改 CSS 变量 `--accent` 和对应的 GSAP 颜色参数
3. 如果改整体配色：重新评估是否需要切换风格，必要时建议运行 Step 1

**最小化修改示例**：
```css
/* 修改前 */
:root { --accent: #E63946; }

/* 修改后：仅改此处，其他不动 */
:root { --accent: #F4A261; }
```

**注意事项**：
- 改色后检查文字对比度，确保仍满足 4.5:1
- 装饰件颜色若使用 `currentColor` 会自动跟随，无需单独修改

---

### 修改请求类型 2：改字体

**用户可能说**："字体太正式了"、"换个圆润一点的"、"用衬线字体"、"换成中文字体"

**响应策略**：
1. 评估新字体与当前风格的兼容性
2. 如果风格兼容：仅替换 `font-family` 声明，调整 `font-weight`
3. 如果风格不兼容（如极简风格要求衬线字体）：说明风格冲突，建议微调风格定位

**最小化修改示例**：
```css
/* 修改前 */
.headline { font-family: 'Inter', sans-serif; font-weight: 700; }

/* 修改后 */
.headline { font-family: 'Playfair Display', serif; font-weight: 700; }
```

**注意事项**：
- 切换字体族（无衬线→衬线）可能影响字号视觉大小，需微调 font-size
- 若使用 Google Fonts，确认在渲染环境中可访问

---

### 修改请求类型 3：加快动画

**用户可能说**："动效太慢了"、"快一点"、"更有节奏感"、"入场太拖"

**响应策略**：
1. 将所有 GSAP duration 按比例缩短（通常缩减 30%-50%）
2. 入场序列的 stagger 间隔同步缩短
3. 如已是最快档（duration < 0.3s），建议改变缓动函数而非继续缩短时长

**最小化修改示例**：
```javascript
// 修改前：标准节奏
gsap.from('.headline', { duration: 1.0, y: 80, opacity: 0, ease: 'power2.out' });
gsap.from('.subtitle', { duration: 0.8, y: 60, opacity: 0, ease: 'power2.out', delay: 0.3 });

// 修改后：加快 40%
gsap.from('.headline', { duration: 0.6, y: 60, opacity: 0, ease: 'power2.out' });
gsap.from('.subtitle', { duration: 0.5, y: 40, opacity: 0, ease: 'power2.out', delay: 0.18 });
```

---

### 修改请求类型 4：减少元素

**用户可能说**："太复杂了"、"东西太多"、"去掉一些装饰"、"更简洁"

**响应策略**：
1. 优先移除装饰层元素（decoration-layer 中的几何装饰件）
2. 其次简化辅助信息（日期、标语等次级内容）
3. 最后考虑合并内容层的文字层级

**决策优先级**：装饰件 → 辅助文字 → 副标题 → 背景纹理

**最小化修改示例**：
```html
<!-- 修改前：3 个装饰件 -->
<div class="deco-circle-large"></div>
<div class="deco-circle-small"></div>
<div class="deco-line"></div>

<!-- 修改后：仅保留最重要的 1 个 -->
<div class="deco-circle-large"></div>
<!-- 移除 deco-circle-small 和 deco-line -->
```

## 三、最小化修改原则

迭代修改时，遵循"最小变动"原则，只修改必须变化的部分：

### 判断修改范围

| 修改类型         | 影响范围           | 操作                        |
|------------------|--------------------|-----------------------------|
| 仅改文字内容     | 单个 DOM 节点      | 只修改 innerHTML            |
| 改颜色           | CSS 变量           | 只改 :root 变量值           |
| 改字体           | font-family 声明   | 只改 CSS font 属性          |
| 改动效节奏       | GSAP 参数          | 只改 duration / delay       |
| 改布局位置       | 位置 CSS           | 只改 top / left / transform |
| 改内容密度       | 增减 DOM 元素      | 增删对应 HTML 块            |

### 只重写变化的帧

如果修改只影响某一帧的某个元素，**不要重新生成整个 composition**。
仅输出该帧中变化的代码段，并明确标注修改位置：

```
// 修改：headline 的颜色由红色改为橙色
// 文件：source/index.html 第 45 行附近
.headline { color: #F4A261; }  // 原值：#E63946
```

## 四、何时建议重新运行 Step 1-3

以下情况说明设计方向需要根本性调整，应建议用户重新启动完整设计流程：

### 触发重新运行的信号

1. **风格方向大改**：用户从"极简商务"转向"赛博霓虹"，或从"温暖有机"转向"冷峻工业"
2. **内容结构大改**：从单帧公告改为多信息数据展示，内容密度从精简变为丰富
3. **目标受众大改**：原为 B2B 企业，现改为 C 端年轻用户
4. **品牌调性大改**：用户反馈"整体感觉不对"而非具体元素问题
5. **连续 3 轮修改仍不满意**：说明初始设计意图推断有误

### 建议话术

> 你的反馈表明我们在初始风格方向上可能存在偏差。
> 建议重新明确设计意图：**你希望传达的核心感受是什么？**（例如：专业可信 / 年轻活力 / 奢华高端）
> 重新定义方向后，我会生成一个与你预期更契合的版本。

## 五、迭代记录格式

每次迭代修改后，在工作记录中追加以下格式的条目：

```
## 迭代记录

### 第 1 轮（初始版本）
- 风格：Swiss Pulse
- 色彩方案：红 #E63946 + 深蓝 #1D3557
- 内容密度：标准
- 决策依据：用户描述"企业公告，专业有力"

### 第 2 轮（2026-07-06）
- 修改类型：调整颜色
- 用户反馈："红色太激进，换个沉稳一点的"
- 修改内容：强调色从 #E63946 改为 #457B9D（中调蓝）
- 修改范围：仅 CSS 变量 --accent，1 处修改
- 决策：保持 Swiss Pulse 风格，仅换色温

### 第 3 轮（2026-07-06）
- 修改类型：加快动画
- 用户反馈："入场太慢了，要更有节奏感"
- 修改内容：所有 duration 缩短 30%，stagger 从 0.3s 改为 0.2s
- 修改范围：GSAP 参数，4 处修改
- 决策：维持 medium 能量等级，向 dynamic 方向微调
```

**记录原则**：
- 每轮记录必须包含：轮次、修改类型、用户原话、具体修改、决策理由
- 用于后续"保存为模板"时作为设计决策的依据
- 格式简洁，每条不超过 5 行
