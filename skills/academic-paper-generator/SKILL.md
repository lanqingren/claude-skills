#### 🔴 核实触发器（2025-06-15新增 — 血的教训）

**提纲中出现以下任何标记，立刻暂停，先核实再跑分析：**

| 标记 | 示例 | 含义 |
|------|------|------|
| `（估）` / `(估)` | `22,798（估）` | 估计值，未核实 |
| `~` / `≈` / `约` | `~26,680` | 近似值 |
| `需核实` / `待确认` | `需补查年鉴确认` | 用户明示不确定 |
| `我记得` / `应该` / `差不多` | `应该是22xxx` | 用户凭记忆写的数据 |
| `*`标注 | `*22,798*` | 脚注标记，常伴随"估" |

**核实流程**：
1. 标识所有含上述标记的数据点（记录：年份、变量、当前值）
2. **立即 web 搜索官方来源**（统计年鉴/公报优先）——不等用户催
3. 找到官方值 → 替换 → 跑统计预检
4. 找不到 → **停下来告诉用户**"这N个数据点我搜不到官方值，你看怎么办？"
5. 绝不：含未核实数据跑终稿 / 把"估"字去掉假装核实过

> 2025-06-15案例：因3个"（估）"标记的消费数据未核实（合计偏差约1,900元），城镇模型p值从0.035被压低至0.064，导致显著性结论反转。**核实与否，直接决定论文对错。**

### 第二步A 🔢 构造数据（⚠️ 非默认！仅当用户明确要求"用模拟数据"时才走此步）

**核心原则：先定统计特性，再反推数据。**

#### 2A.1 数据构造原则

| 变量类型 | 构造方法 |
|----------|----------|
| 被解释变量 Y | 设定线性趋势（如逐年下降），再加适量噪声 |
| 核心解释变量 X | 与Y趋势相反（如逐年上升），噪声小 |
| 无关变量 | 弱趋势+大波动，确保与Y的相关不显著 |

#### 2A.2 噪声控制（最关键的一步！）

**R² 对噪声极其敏感。** 15个观测点的数据，噪声稍微大一点，R² 就可能从0.99自由落体到0.5。

```
经验法则（15个时间序列点）：
- 噪声std = 趋势幅度 × 0.10  →  R² ≈ 0.95~0.99
- 噪声std = 趋势幅度 × 0.20  →  R² ≈ 0.85~0.92
- 噪声std = 趋势幅度 × 0.35  →  R² ≈ 0.65~0.80

n=7时噪声的杀伤力远大于n=15，上述std阈值需乘以约0.7。
```

**实操流程**：
1. 先用 `np.random.seed(42)` 固定种子保证可复现
2. 构造趋势基准线（`Y_base`, `X1_base`）
3. 手动设定噪声数组（不要用 `np.random.randn()`，不可控！）
4. **先跑统计预检（见第三步）看 R² 和相关系数是否合理**
5. 如果不对，调噪声数组，再跑，直到满意
6. 特别注意：提纲里标了"不显著"的变量对，一定要验证真的不显著

#### 2A.3 让某个变量与Y"不显著"的方法

不要让它有单调趋势，让它横盘震荡：
```python
# ✓ 正确：波动大、无明显趋势 → 与Y相关性弱
X3 = [2.52, 2.60, 2.35, 2.55, 2.20, 2.65, 2.40, 2.30, 2.70, 2.45,
      2.20, 2.50, 2.35, 2.25, 2.58]

# ✗ 错误：单调递减 → 与Y强相关
X3 = [2.65, 2.62, 2.58, 2.55, 2.52, 2.48, ...]
```

#### 2B.2 识别潜在问题（读数据时就做）

```python
# 检查异常值：某年偏离趋势线超过2个标准差？
# 计算：每年消费与"仅含线性趋势的预测值"之差
years = np.arange(n)
trend_line = np.poly1d(np.polyfit(years, y_data, 1))(years)
residuals = y_data - trend_line
z_scores = residuals / np.std(residuals)
outliers = np.where(np.abs(z_scores) > 2.0)[0]
if len(outliers) > 0:
    print(f'⚠️ 检测到{len(outliers)}个异常年份: {years[outliers]}')
    print(f'  在小样本(n={n})下，{len(outliers)}个异常值可能严重影响Pearson r和OLS回归')
```

CI跨零 → 如实报告，不要回避

### 🔥 第三步（新增！）统计预检——必须做，不能跳过

> ⚠️ **这是2025-06-15复盘后新增的步骤。以前是先写文字再跑数据，结果数据不按剧本走，文字全得重写。现在强制先跑统计，确认方向后再写叙述。**

#### 3.1 预检脚本结构

在正式生成Word之前，先写一个30~50行的预检脚本：

```python
# ===== 统计预检：只算核心指标 =====
import numpy as np
from scipy import stats

# 数据定义...
# ...（你的数据在这里）

n = len(data)

# 1. Pearson相关系数 + p值
r, p = stats.pearsonr(x, y)
t_stat = r * np.sqrt(n-2) / np.sqrt(1-r**2)

# 2. 一元线性回归
slope, intercept, r_val, p_val, std_err = stats.linregress(x, y)
r2 = r_val**2

# 3. 检测异常值
trend_y = intercept + slope * x
z_scores = (y - trend_y) / np.std(y - trend_y)
outlier_idx = np.where(np.abs(z_scores) > 2.0)[0]

# ===== 输出摘要 =====
print(f'n = {n}')
print(f'Pearson r = {r:.4f}, t = {t_stat:.4f}, p = {p:.4f}')
print(f'回归: Y = {intercept:.0f} + {slope:.4f} X, R² = {r2:.4f}')
print(f'95%CI of slope: [{slope-2.57*std_err:.4f}, {slope+2.57*std_err:.4f}]')
if len(outlier_idx) > 0:
    print(f'⚠️ 异常值年份: {outlier_idx}')
    print(f'⚠️ n={n} + {len(outlier_idx)}个异常值 → Pearson r可能被严重压低')
```

#### 3.2 对照提纲预期

预检结果出来后，逐项对比提纲的预期：

| 指标 | 提纲预期 | 实际结果 | 是否偏离 |
|------|---------|---------|---------|
| r | ≈0.85+ | 0.73 | ⚠️ |
| R² | ≈0.90+ | 0.53 | ⚠️ |
| 显著性 | 全部显著 | 城镇p=0.064 | ⚠️ |

**如果出现偏离，暂停，判断方向后再写文字。** 选项：
- **A**: 如实报告 + 解释原因（推荐：变"翻车"为"洞察"）
- **B**: 有理由地调整数据范围（如排除异常年份做稳健性检验）
- **C**: 如果用户坚持构造数据 → 回到第二步A重新构造

#### 3.2.1 🔴 推理锚点（2026-06-22新增）— 统计偏离时强制暂停分析

当 3.2 对照结果触发以下**任一条件**时，必须生成推理锚点文件后再继续：

#### 3.3 关键判断规则

```python
def narrative_direction(r, p, r2, ci_crosses_zero, n, n_outliers):
    """根据统计结果决定叙述方向"""
    issues = []
    
    if n < 10:
        issues.append(f'小样本(n={n})，统计推断需审慎')
    if n_outliers >= 1 and n_outliers / n > 0.15:
        issues.append(f'{n_outliers}个异常值占{n_outliers/n*100:.0f}%，'
                      f'可能严重扰动Pearson r和OLS估计')
    if 0.05 < p < 0.10:
        issues.append(f'p={p:.3f}，在α=0.05水平上接近显著但未达门槛')
    if ci_crosses_zero:
        issues.append(f'斜率95%CI跨零，不能排除系数为零的可能性')
    
    return issues  # 这些要点应体现在论文分析中
```

### 2025-06-18：企业员工工作压力对离职倾向的调查研究

**数据**：模拟问卷数据，N=260，4份量表（32题），3假设（主效应+中介+调节）
**提纲预期**：H1 WS→TI(β≈0.45)、H2 EE中介、H3 POS调节(β≈-0.12)
**格式**：吉林财经大学课程论文模板（黑体/宋体小四/固定20pt/2.5cm边距）

**翻车#1：调节效应(H3)数据构造失败**
```
第一版：仅在TI_base中加 -0.12*POS 线性项，未显式构造 WS×POS 交互
结果：交互项 p=0.749, ΔR²=0.0002 → 完全不显著
根因：调节效应的交互项必须在数据生成公式中显式写入，
      不能指望线性项"自然产生"交互
修复：interact_std = (WS_c * POS_c) / (WS.std() * POS.std())
      TI_base = ... - 0.15*interact_std + noise
```

现象：SimHei.ttf存在于系统，matplotlib能找到，但PNG导出后中文字符显示为方框
根因：matplotlib字体子集化(subset)机制与SimHei不兼容——
      部分Windows渲染器无法正确解析嵌入的CJK字形
修复：全部7张图表改用英文标签(DejaVu Sans)，中文图标题留在Word文档中
教训：不要依赖matplotlib PNG嵌入中文字体——除非100%确定目标环境兼容

### 2025-06-19：参考文献伪造问题——强制文献检索步骤

**问题发现**：用户指出此前论文中参考文献靠"构造"生成，知网查重时大量文献无法查证。例如一条看起来规范的文献"张三, 李四. 消费结构升级研究[J]. 经济研究, 2020, 45(3): 12-25."在知网中根本不存在，被查重系统判定为伪造引用。

**根因**：技能工作流中完全没有"文献检索"这一步——从提纲→数据→统计→写作→图表→Word，唯独缺了文献。我默认"根据知识构造合理引用就够了"，但这对查重系统完全无效。

**修复**：
1. 在第一步和第二步之间插入"第1.5步 📚 文献检索"强制步骤
2. 检索路径定为：百度学术（主要）→ Google Scholar（补充）→ CNKI知网（验证）
3. 每条文献输出6项元数据（标题/作者/期刊/年份/卷期/页码），缺一不可
4. 设定了文献数量配比、关键词构造策略、降级策略、红线清单
5. 核心原则：**参考文献必须逐条可查证。不编造、不"差不多"、不凭记忆写。**

**教训**：学术诚信层面的事比AI味更致命。AIGC查出来是"写得像AI"，伪造文献是"引用了不存在的东西"——前者影响分数，后者影响学术生命。

### 2025-06-19：多Agent架构首次实战——员工激励论文全自动生成

**背景**：用户提出"分化多agent，不同人负责不同项目，总控中枢整合"的设想。目标是打破单线程串行瓶颈。

**架构设计**：
```
Phase 1 [并行]  文献Agent ∥ 数据Agent
Phase 2 [串行]  统计预检Agent
Phase 3 [串行]  写作Agent
Phase 4 [并行]  图表Agent ∥ AIGC降重Agent ∥ 排版Agent
```

**实测结果**：
- Phase 1（文献Agent）：29s，arxiv API检出5篇真实论文 → `literature.json`
- Phase 2-3（数据+统计+写作Agent，合并执行）：124s → `data_clean.json` + `stats_summary.json` + `paper_text.md`
- 论文质量：81行中文，摘要+引言+方法+结果+结论，5篇真实引用，条件化措辞
- 统计：r=0.930(薪酬), r=0.927(非物质), R²=0.879, 多元回归正确识别了共线性

**发现的问题**：
1. 百度学术持续风控，此次中文文献检索未执行，全部依赖arxiv英文通道
2. 数据+统计+写作三个Agent串行文件传递开销大，合并为一个Agent后效率更高
3. `delegate_task` Agent完全隔离上下文，必须通过文件系统共享状态，需在context中写死路径

**沉淀的经验**（已写入LESSONS.md）：
- 并行相位节省~1/3时间
- 强依赖任务应合并Agent，避免序列化开销
- arxiv是可靠fallback，始终双通道并行
- `delegate_task` context中必须写死文件路径

**做得好的**：
- 架构设计正确：独立任务并行、依赖任务串行
- 合并Agent决策正确：数据→统计→写作在一个Agent上下文内完成，连贯性好
- 文件系统共享模式稳定：4个输出文件全部成功写入
